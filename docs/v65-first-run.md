# v65 · 최초 운동 설정 (Figma FINAL/01, FINAL/02)

상태: 구현 완료(코드). 검증은 CI 결과 기준이며 실기기·Watch4 검증은 하지 않았다.

## PO 확정 기록 (2026-11-16, 사용자 지시 "PO확정해")
아래 3개만 확정으로 본다. 다른 미확정 항목(마일스톤 기준, 칼로리 표시, 헬스장 검색 등)은 이 지시에 포함되지 않는다.
1. 운동 목적 선택지는 Figma FINAL/01의 4개(체중 관리, 근력 향상, 체력 향상, 운동 습관)이며 단일 선택이다. 목적은 저장만 하고 추천 등에는 아직 반영하지 않는다.
2. "선택 전에는 루틴 추천·운동 시작을 할 수 없어요"는 **새 사용자에게만** 적용한다. v58 기록·저장 세션·등록된 공간이 있는 기존 사용자는 설정 화면에 막히지 않는다.
3. ROUTIVE 심볼(R 로고) 에셋이 들어오기 전까지는 글자 "ROUTIVE"만 표시한다.

## 흐름
1. FINAL/01 목적: 체중 관리 / 근력 향상 / 체력 향상 / 운동 습관 중 **하나**(라디오). **처음에는 아무것도 선택되지 않으며** 선택 전에는 "운동 공간 선택" 버튼이 비활성이다. 계속하면 목적을 저장한다.
2. FINAL/02 공간: "집에서 운동하기"(집 · 개인 운동 공간을 만들고 기본 공간으로 설정) 또는 "헬스장에서 운동하기"(헬스장 이름 직접 입력). 공간이 저장되어야 설정 완료로 표시한다.
3. 완료하면 오늘 화면 위에 새 공간의 보유 기구 화면이 열린다. 기구·모델은 나중에 등록해도 된다.
설정 화면에서는 하단 탭을 숨긴다.

## 누구에게 보이는가 (FirstRunPolicy)
- 설정을 끝내지 않았고, **v58 운동 기록도 저장된 세션도 등록된 공간도 없을 때만** 보인다.
- 기존 사용자는 업그레이드 후에도 설정 화면에 막히지 않는다(Figma 02의 "선택 전에는 운동 시작을 할 수 없어요"는 새 사용자에게만 적용). 읽기에 실패하면 "기존 사용자"로 본다.
- 목적은 마이 > 운동 목적에서 언제든 바꿀 수 있다.

## 테스트
- JVM `FirstRunTest`: 판정 표, 새 설치, v58 기록/저장 세션/공간이 있는 사용자, 완료 표시, 목적 저장, 알 수 없는 값.
- 에뮬레이터 `ComposeFirstRunTest`: 강제 실행 extra(`move60_force_first_run`)로 목적 → 공간(헬스장) → 보유 기구 → 마이에서 목적 변경, DB와 저장 값 확인.
- 클린 에뮬레이터는 "기록 없음" 상태라 기존 테스트가 모두 설정 화면에 걸린다. 그래서 `Move60TestRunner`가 테스트 시작 전에 설정을 완료 처리한다(`app/build.gradle`, `scripts/smoke-phone-features.sh`의 러너 이름도 변경).

## 만들지 않은 것
- 목적은 저장만 하고 **추천 등에 반영하지 않는다**(위 확정 1).
- Figma의 ROUTIVE 심볼(R 로고)은 승인된 브랜드 에셋이라 새로 만들지 않았고, 글자 "ROUTIVE"만 표시한다. 에셋이 들어오면 교체한다.
- 선택 전 운동 시작 차단은 새 사용자에게 설정 화면을 먼저 보이는 것으로 구현했다. 오늘 화면 자체의 별도 차단 상태는 없다.
