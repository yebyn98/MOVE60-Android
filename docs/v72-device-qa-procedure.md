# v72 · 실기기 QA 절차서 (Android 폰 + Galaxy Watch4) — 사용자 수행용

**이 문서는 절차서이며 결과가 아니다. 이 문서에 적힌 항목 중 실기기에서 실제로 확인된 것은 하나도 없다.** CI·에뮬레이터 통과를 실기기 통과로 쓰지 않는다. 체크리스트의 기준은 이슈 [#58](https://github.com/yebyn98/MOVE60-Android/issues/58)이고, 이 문서는 항목별 **절차·기대 결과·증빙**을 붙인 것이다(#58은 수정하지 않았다).

## 0. 공통 준비·증빙 서식
- 기기: 폰(모델·Android 버전), Galaxy Watch4(Wear OS 버전), 폰과 워치 페어링 상태.
- **v58 설치본**과 **v2 빌드**(서명 키가 같은 빌드). 테스트 전 폰에서 v58 기록을 백업하거나 테스트 전용 기기를 쓴다.
- 항목마다 기록: `기기/OS/앱 버전 · 일자 · 결과(통과/실패/미수행) · 스크린샷 또는 로그 · 비고`.
- 실패하면 원인을 추측하지 말고 화면 캡처와 시각을 남긴다.

## A. 데이터 보존 (P0)
| # | 절차 | 기대 결과 |
|---|---|---|
| A1 | v58에서 운동 3일치(근력 세트 무게·횟수 포함) 기록, 도전 1개 생성. 앱을 **삭제하지 않고** v2로 덮어 설치 | 설치 성공. 기록 달력의 날짜·운동시간·세트 값·도전 진행이 설치 전과 같다. 기록 화면에 같은 날 **세션이 2개로 보이지 않는다**(구기록·신기록 중복 없음) |
| A2 | 설치 직후 앱을 연다 | 첫 운동 설정 화면이 **기존 사용자에게 나오지 않는다**. 기록 화면 첫 진입에 칼로리 안내 배너가 **1회만** 나온다(승인 문구). 오늘·기록·마이 어디에도 kcal 숫자가 없다 |

| A4 | 새 운동 시작 → 일시정지 → 세트 기록 → 단계 넘김 → 종료 → 앱 재실행 | 값이 같고, 세션이 1개만 저장된다 |
| A5 | 운동 중(세트 2개 완료) 최근 앱 목록에서 앱을 **강제 종료** 후 재실행 | 진행 중인 운동·세트·경과 시간이 유지된다. 휴식 타이머가 돌던 중이면 남은 시간이 이어진다 |
| A6 | 화면 끄기, 백그라운드 5분 후 복귀 | 타이머·기록이 정상이고 중복 기록이 없다 |
| A7 | 자정 전후에 걸쳐 운동 | 날짜별 활성 시간이 나뉘어 집계되고, 하루 활성 600초 이상일 때만 운동일로 인정 |
| A8 | 저장 공간이 거의 찬 기기에서 운동 완료 → 공간 확보 후 재시도 | 오류 안내가 나오고, 재시도 후 기록이 **1개만** 남는다 |
| A9 | 데이터 없음 / 조회 실패 / 미수행 화면 | 서로 다른 문구로 구분된다 |

## B. 폰 화면·알림 (P0)
| # | 절차 | 기대 결과 |
|---|---|---|
| B1 | 운동 중 폰 **잠금** → 알림 확인(OS별: 가능하면 Android 12/13/14/15 중 2개 이상) | 잠금화면에 종목·단계·남은 시간·기록 등 상세가 보이지 않고 일반 문구("운동 진행 중 / 잠금을 해제하면 자세히 볼 수 있어요")만 보인다. 잠금 해제 후 상세가 보인다 |
| B2 | 시스템 설정의 "민감한 알림 숨기기"를 바꿔 B1 반복 | 시스템 설정과 충돌하지 않는다 |
| B3 | 알림을 눌러 앱으로 복귀 | 진행 중인 운동 화면으로 돌아온다 |
| B4 | 설정 > 오픈소스 라이선스 | 목록이 열리고 닫힌다(전이 의존성이 아직 포함되지 않았다는 안내 확인 — `docs/v70`) |
| B5 | 앱 이름·아이콘 | 런처·위젯·알림·시작 화면에 "ROUTIVE"로 보인다(아이콘 그림은 PO 결정 대기) |
| B6 | 운동 구성 화면 | 기본 공간과 등록 기구가 보이고, 근력 선택창에 "보유 기구에 맞는 운동"(승인된 행만)과 "직접 구성"이 보인다 |

## C. Galaxy Watch4 (P0, 이 환경에서 확인 불가)
| # | 절차 | 기대 결과 |
|---|---|---|
| C1 | 워치 앱 설치·실행, 폰과 연결 | 설치 성공. 연결 상태는 **실제 감지로만** 표시(저장된 기기명만으로 "연결됨" 금지) |
| C2 | 폰에서 운동 시작 → 워치에서 단계·일시정지·종료 | 폰과 워치 상태가 서로 동기화된다 |
| C3 | **폰 화면을 닫은 채 워치에서 마지막 단계 완료** | 폰을 열지 않아도 기록과 도전 실적이 반영되고, 폰을 열었을 때 세션이 2개로 보이지 않는다 |
| C4 | 심박: 권한 허용 / 거부 / 미수신 / 연결 끊김 | 각 상태가 구분되어 표시되고, 오래된 값을 현재 값처럼 보이지 않는다 |
| C5 | 타일, Ambient, 진동, 재실행, 배터리 | 정상 동작. 타일·워치 화면에 kcal이 없다 |
| C6 | 이미 칼로리 측정을 켠 워치 사용자 | "측정 끄기"만 보이고 끄면 폰으로 전송되지 않는다 |
| C7 | 화면 꺼짐·백그라운드·연결 해제 후 복구 | 상태가 복구되고 기록이 유지된다 |
| C8 | 워치 페이스의 Ongoing Activity | 단계 이름 표시(PO 결정: 숨기지 않음) |

## D. 출시 필수 (P0, 사람·외부)
- 개인정보처리방침 **실제 HTTPS URL**을 앱과 Play Console에 같은 값으로 반영, 건강 데이터(심박) 실제 수집·보관·삭제·제공 항목과 문구 대조.
- 오픈소스 고지 의무 검토(`docs/v70`), `verify-release-legal.py` 통과(URL 반영 후), 릴리스 APK/AAB 설치·기능 확인.
- 앱 버전(`versionCode`는 58보다 커야 한다)·서명·Play Data Safety 입력.

## E. 에뮬레이터와 실기기의 범위 구분
| 영역 | CI/에뮬레이터로 확인되는 것(자동) | 실기기로만 확인 가능한 것 |
|---|---|---|
| 폰 화면 | 스모크 96개 안팎의 계측 테스트(화면 이동, 기록·도전·마이, 설정, 첫 설정, 접근성 대상 등), 업그레이드 테스트(Room v1 파일 → 최신) | 실제 v58 앱 위 덮어쓰기, 다양한 해상도·폰트 크기, 프로세스 강제 종료, 저장 공간 부족 |
| 알림 | 알림이 NotificationManager에 올라오는지 | **잠금화면 공개 범위**(OS별), 시스템 설정과의 상호작용 |
| Wear | Wear OS 에뮬레이터(API 34, 작은 원형 396×396)에서 `WatchDisplayTest` 16개 + `WearHealthScreenTest` 3개(레이아웃·화면 조작) | 폰↔워치 실제 연결·동기화, **실시간 심박**·권한, 타일·Ambient·진동·배터리, 폰 닫은 채 워치 완료 |
| 데이터 | JVM 313개 안팎(마이그레이션·세션·중복 저장·정정), 정적 데이터 안전성 가드 | 실제 사용자 데이터 규모에서의 업그레이드 |
