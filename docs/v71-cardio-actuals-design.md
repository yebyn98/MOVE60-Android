# v71 · Phase 3-2 설계안: 유산소 실측·강도 구간 기록

**상태(2026-11-17): PO 확인 4건 확정. 1단계(순수 계산기 `CardioIntervals`)만 구현·JVM 테스트. DB·화면·워치는 아직 없다. CI·에뮬레이터·실기기 미검증.** 근거: Notion "ROUTIVE v2 · 2026-11-17 Figma 정리·정책 9건·QA/플로우 이관 기록" §8(P-08 확정 기준·사례 A~E·AC-P08-01~06), 기존 `docs/v60`~`v63`, 현재 코드.

## 1. 요구 (정책 원문 요약)
- 실제 기구 수치를 **선택 입력**한다. 입력 사건(원본)과 사후 정정은 구분해 보존한다. 미기록 구간의 수치는 **추정하지 않는다**.
- 강도별 **시작·종료 경과시간**을 남긴다. **일시정지 시간은 제외**한다(운동 경과시간 기준).
- 종료 후 실제 기록을 수정할 수 있다. **정정 전·후 값과 수정 시각**을 보존하고, 저장 실패 시 원본을 유지하며 재시도할 수 있다.
- 기록 상세에서 실제 강도 구간을 본다. 조회·저장 실패는 "미기록"이나 0과 구분한다.
- 사례(확정): A 시작부터 입력(3→5→7, 각 5분) / B 첫 입력이 늦음(앞 5분은 **미기록**, 소급 적용 금지) / C 입력 중 취소(변경 없음) / D 일시정지(제외) / E 사후 정정(원본 입력 불변).

## 2. 현재 코드 상태 (직접 확인)
| 영역 | 상태 |
|---|---|
| `session_segments`(v2~) | `kind`(`CARDIO_WORK`/`CARDIO_RECOVERY`/`CARDIO_STEADY` 포함), `equipment`, `actualSeconds`, `metricsJson`(사용자 입력 콘솔 값). **한 구간당 한 스냅샷**이라 "입력 시점별 이력"을 담을 수 없다 |
| `session_adjustments`(append-only) | `field`/`oldValue`/`newValue`/`createdAt`/`reason`. 지금은 근력 세트의 중량·횟수만(`set:<운동>:<번호>:<속성>`), `CorrectionField.parse`는 그 밖의 필드를 null로 거른다 |
| 4단계 진행 | 단계별 경과(`FourStageProgress`)와 일시정지 제외 활성시간이 이미 있다 |
| 저장 경로 | `TimerSnapshot` → `PendingSessionOutbox`(JSON, 내구) → 멱등 커밋(`SessionCommitter`). 구버전 outbox 항목은 읽을 수 있어야 한다 |
| UI | 세션 화면에 유산소 값 입력 없음. 기록 상세에 "실제 강도 구간" 없음(`docs/v60`: 미구현) |
| 기구 | `Equipment.cardio`: 실내 사이클, 일립티컬(브랜드·모델 선택 입력만 있음) |

## 3. 설계 원칙
1. **원본 입력 사건은 추가만**(덮어쓰기·삭제 없음). 구간은 입력 사건에서 **계산**한다(저장하지 않아 불일치가 생기지 않는다).
2. 시각은 **세션 활성 경과 초**로 저장한다(일시정지 자동 제외, 벽시계와 분리).
3. 첫 입력 이전과 입력이 없는 구간은 **미기록**으로 남긴다. 목표 강도·직전 값으로 채우지 않는다.
4. 정정은 기존 `session_adjustments`에 **새 행 추가**(원본 입력 사건 불변).
5. 칼로리·강도·시간을 만들어 내지 않는다.

## 4. 데이터 모델 제안 (Room v7, 추가만)
```
session_cardio_inputs
  sessionId TEXT, inputIndex INTEGER            (PK)
  stageIndex INTEGER                            유산소 ①/②
  atActiveSeconds INTEGER                       세션 활성 경과(일시정지 제외)
  equipmentKey TEXT                             Equipment 키(예: INDOOR_CYCLE)
  metricKey TEXT, valueText TEXT, unit TEXT     사용자가 입력한 그대로
  enteredAtEpochMs INTEGER                      입력 시각(감사용)
```
- 마이그레이션은 `CREATE TABLE IF NOT EXISTS` 한 개뿐이다. **기존 테이블은 건드리지 않고** 기존 기록은 불변이다. `exportSchema` 7.json 추가, `RoutiveMigrationTest` 패턴으로 v6→v7 테스트, `verify-data-safety.py`(DROP·RENAME 금지, 스키마·마이그레이션 사슬) 통과 필수.
- 정정 필드: `cardio:<inputIndex>:<metricKey|at>`. `CorrectionField`에 파서만 확장(스키마 변경 없음).
- outbox/`TimerSnapshot` JSON에 `cardioInputs` 배열을 **버전 필드와 함께** 추가한다. 필드가 없는 구버전 항목은 "입력 없음"으로 읽는다(호환 테스트 필수).

## 5. 기록 흐름
1. 유산소 단계에서 "강도 입력"을 누르면 기구 수치 선택/입력 시트가 열린다. **저장을 눌렀을 때만** 입력 사건이 생기고, 취소는 아무것도 만들지 않는다(사례 C).
2. 구간 = 입력 사건 ~ 다음 입력 사건(또는 해당 유산소 단계 종료). 첫 입력 이전은 미기록(사례 B).
3. 종료 시 입력 사건은 기존 세션 커밋과 **같은 트랜잭션**으로 저장한다(실패 시 outbox에 남아 재시도, 중복 없음).
4. 기록 상세: "실제 강도 구간" 목록(기구 수치·지속시간·미기록 표시)과 수정 시트. 조회 실패는 오류+재시도, 입력이 없는 세션은 "수치 미기록".
5. 수정: 값만 정정하면(시각은 수정 불가) `session_adjustments`에 이전·새 값·시각이 추가되고 원본 입력은 그대로다. 저장 실패 시 기존 유효 기록 유지, Draft·재시도(근력 정정과 같은 방식).

## 9. 위험
- DB 스키마 변경(v7)은 개발 브랜치의 다른 작업과 충돌하기 쉬워 **다른 데이터 계층 변경이 없을 때 단독 PR**로 진행해야 한다.
