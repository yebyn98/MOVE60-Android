# 정책 5 — SetRecordStore 기존 세트 기록 가져오기 (A안, 2026-11-16 PO 승인)

## 정책 요약
- v58에 저장된 **완료 세트**를 v2 기록 상세에서 저장된 값 그대로(날짜·종목·세트 번호·중량·횟수) 조회한다.
- 기존 세션과의 연결이 확인되면 그 세션의 근력운동 항목 아래에, 확인되지 않으면 시간·세션을 만들지 않고 "이전 버전에서 저장한 기록"으로 따로 표시한다.
- 미완료 세트, 임시 입력값(토큰 0), 중복 기록은 완료 기록으로 바꾸지 않는다.
- SharedPreferences 원본은 삭제·변경하지 않는다. 도전 인정일·활성 운동시간·세션 수는 늘리지 않는다.
- 기존 기록 수정은 v2 기록 정정 정책(P-22·P-23)에 따라 원본과 정정 이력을 분리한다(이번 범위 아님).

## 구현 방식: 읽기 전용 조회 (복사본을 만들지 않음)
- `SetRecordStore.completedStoredSets()` — 키 `set:<날짜>:<요일>:<토큰>:<종목ID>:<세트>`를 정확히 6토막으로 해석하고, 토큰 > 0 · 완료 · 값 유효인 세트만 반환. 쓰기 없음.
- `LegacySetReader.forDate(date)` — 같은 요일·토큰끼리 묶고, 세션 ID `timer-<날짜>-d<요일>-<토큰>`이 **정확히 일치하는** 저장 세션이 있을 때만 연결. 연결된 경우 저장된 세트(STORED)를 먼저, 저장본에 없는 이전 버전 세트(LEGACY)를 추가하고, 값이 똑같은 중복은 한 번만 보여준다. 값이 다르면 둘 다 보여주고 "저장된 값과 달라요"로 표시한다.
- 화면: 기록 탭 일자 상세 카드 아래 "근력운동 세트 기록" (`calendar_set_records`). Figma 27 최종 레이아웃은 아직 구현하지 않음.
- 복사본을 만들지 않으므로 반복 실행·재시도·실패가 중복이나 원본 훼손을 만들 수 없다(구현 조건 2·4). Room 스키마 변경 없음.

### 복사 저장 방식을 택하지 않은 이유 (PO 확인 필요)
복사 저장은 Room v6 마이그레이션과 `schemas/6.json` 생성이 필요한데, 이 개발 환경에는 Android SDK가 없어 스키마를 생성·검증할 수 없다. 사용자 데이터 보존이 최우선이므로, 검증 없이 스키마를 바꾸는 대신 쓰기 없는 조회로 AC를 충족시켰다. 복사 저장(출처 열이 있는 별도 테이블)이 꼭 필요하면 후속 작업으로 분리한다.

## 연결 규칙의 근거
`TimerSessionSync`가 저장하는 세션은 `legacyToken = null`, `startedAtEpochMs = 첫 구간 시작`이라 토큰과 같다고 볼 수 없다. 토큰을 신뢰성 있게 담고 있는 것은 세션 ID뿐이므로 ID 일치만 연결 근거로 쓴다. 불일치·부재는 연결하지 않는다(추측 금지).
