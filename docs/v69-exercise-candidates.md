# v69 · "보유 기구에 맞는 운동" 후보 (Phase 3-1)

**구현 완료와 QA 검증 완료는 별개다. 이 문서의 구현은 코드·로컬 테스트까지이며, CI와 실기기 결과는 PR 본문에 따로 쓴다.**

## 동작 (PO 확정 원칙)
- 후보는 **기본 운동 공간 1곳**의 등록 기구만 본다. 다른 공간의 기구는 합치지 않는다.
- 맨몸 운동(매트·벽·의자 운동 포함)은 기구 없이 후보가 된다. "A 또는 B"는 하나만 있으면 후보다. "벤치+덤벨"은 둘 다 필요하다.
- **승인된 행만 후보에 나온다.** 현재 35행 전부 승인됐다. 승인되지 않은 행은 기구가 있어도 나오지 않는다. 후보에 없는 운동은 "직접 구성 · 모든 운동"에서 기존처럼 고를 수 있다.
- 운동 목적은 저장만 하고 후보에 쓰지 않는다. 세트·횟수·무게·강도·시간은 만들지 않는다.
- 후보가 없으면 빈 상태 문구와 직접 구성이 보인다. 공간이 없음과 불러오기 실패는 다른 문구로 구분한다. 구성 화면의 고정 문구("등록된 기구가 아직 없어요 / 등록된 기구 + 맨몸 동작만 운동 후보에 포함")는 실제 데이터로 바꿨다.
- 코드: `domain/ExerciseEquipmentRules.kt`(규칙표), `architecture/DefaultSpaceEquipment.kt`, `RoutineComposeViewModel.candidates()`, `RoutineComposeScreen`.

## 승인 현황 (35행) — 전부 승인
- PO가 이 대화에서 행별로 결정한 13행(매트 운동 6개·벽 푸시업·의자 스쿼트는 맨몸, 카프레이즈는 맨몸 또는 덤벨, 리버스 런지·클램셸·힙쓰러스트·팔로프 프레스는 "A 또는 B"는 하나만 있으면 후보)에 이어, **"나머지 승인"(2026-11-17)으로 나머지 22행도 승인됐다.** 코드의 모든 행이 `approved = true`다.
- 승인 근거와 범위는 대응표(`docs/v67-exercise-equipment-mapping-draft.md`)의 35행이다. 로프는 케이블 머신에, 미니밴드는 저항 밴드에 포함하고, "벤치+덤벨"(덤벨 체스트프레스)은 둘 다 있어야 후보다.
- `approved` 플래그는 남겨 둔다. **앞으로 추가되는 운동은 PO가 그 행을 승인하고 `true`로 바꾸기 전에는 후보가 아니다.**

## 알려진 한계
- 후보는 근력 운동 선택에만 적용된다(유산소·준비·정리 단계는 규칙표가 없다).
- 직접 구성 목록은 기존대로 **오늘 요일의 운동 풀**이고, 후보는 35개 전체에서 계산한다. 그래서 오늘 풀에 없는 맨몸 운동도 후보 구역에는 보인다.
- 요가 매트 기구 자체는 등록 목록에 남아 있지만, 매트 운동은 맨몸으로 분류했으므로 후보 판단에는 쓰이지 않는다.
- 검증: JVM 326개(로컬), 화면 확인은 CI 캡처로 한다. 실기기 확인 없음.
