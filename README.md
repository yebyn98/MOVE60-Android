## 1. 프로젝트 개요와 변경 불가 요구사항

- Android 패키지명: `com.move60.workout`; **Kotlin 네이티브 UI** (메인에 Java / WebView / HTML / JS 다시 도입하지 말 것).
- 삼성 갤럭시(Android 16 / One UI 포함)에서 사용할 개인용 운동 플래너.
- **월요일~금요일, 매일 총 60분**: 준비운동 + 실내 사이클 + 근력운동 + 마무리 스트레칭. 날짜마다 운동 부위·강도 차별화.
- 한 주의 운동 선택은 동일 주 안에서 고정되고 다음 주에 바뀜. 원본 운동 종류·운동방법·주의사항·세트·횟수·운동 데이터 **임의 삭제/변경 금지**.
- 화요일 실내 사이클: **30분, 18개 구간** (4분 워밍업 + [1분 빠르게 / 2분 회복] × 8 + 2분 쿨다운). 사이클 체크리스트와 실시간 타이머 구간은 일치해야 함.
- 운동 타이머는 앱 밖에서도 시간 흐름 유지; 일시정지·재개·이전/다음 단계·체크리스트·진행률·운동 상세 화면 보존.
- UI 레이아웃: 상단에 여백 확보, 요일별 단계 시간은 카드 중앙 정렬, **'오늘의 운동 체크 현황'은 '운동 순서 · 체크리스트' 바로 위**.
- 업데이트는 화면 상단의 **작은 버튼** 또는 정돈된 설정 영역에서 진입.
- **운동 중 알림창은 단순 텍스트가 아니라 카드형 타이머**(운동명, 남은 시간, 단계, RPE, 진행률 등). **잠금화면에도 가능하면 타이머 표시**, 단 Android/One UI 정책이 레이아웃과 표출을 제한할 수 있으며 실기기 검증 필요.
- 데이터를 지키기 위해 **업데이트 설치 시 기존 앱 삭제·데이터 삭제를 기본 해결책으로 제시하지 말 것**.

## 3. 지금까지 발생했던 문제와 재발 방지 규칙

### A. 앱을 켜자마자 종료되거나, 운동 시작 직후 강제 종료

**실제 확인된 원인:** v12 이전의 카드형 알림에 들어 있던 **일반 `<View>`**는 `RemoteViews`에서 지원되지 않아 Android가 알림을 렌더링할 때 다음 예외가 발생했습니다.

```text
BadForegroundServiceNotificationException
Error inflating class android.view.View
```

- **Foreground Service 알림의 RemoteViews에는 Android가 지원하는 뷰만 사용**합니다. 일반 레이아웃에서 정상인 요소도 알림 레이아웃에서는 실패할 수 있습니다. 빈 공간은 지원되는 `TextView` 또는 부모 레이아웃의 여백·중력·패딩으로 구현합니다.
- `RemoteViews`를 사전에 `contentView?.apply(context, null)` 식으로 렌더링하지 않습니다. 이전 구현에서 이 부분이 예외/텍스트 폴백을 유발할 수 있었습니다.
- `NotificationManager.notify()`와 `startForeground()` 성공만으로 안전하다고 판단하지 않습니다. **Android SystemUI가 나중에 알림 뷰를 부풀리면서 앱 프로세스를 종료시킬 수 있습니다.** AndroidRuntime 로그, 실제 앱 프로세스 생존 여부까지 확인합니다.
- 실행 중 서비스가 비정상 종료됐을 때 이전 운동 기록을 **지우지 않고** 복구 화면/오류 로그를 확인합니다. 자동 서비스 재시작으로 재차 크래시가 나지 않도록 주의합니다.
- 예외를 무작정 삼키고 사용자를 텍스트 알림으로 되돌리는 방식은 **카드형 디자인 완료의 증거가 아닙니다**.

### B. 알림창에 텍스트만 보임 / 잠금화면에 알림이 없음

- 카드 XML 작성만으로 해결됐다고 주장하지 않습니다. **운동 시작 → 상단 알림창 열기 → 실제 카드 시각 확인 → 화면 잠금 → 알림 존재·타이머 시각 확인**을 별도로 검증합니다.
- Foreground Service가 살아 있는지, `POST_NOTIFICATIONS` 승인 여부, 앱 전체 알림 허용 여부, **운동 진행 채널 importance**, 잠금화면 노출 설정, 사용자 기기 제조사 정책을 구분합니다.
- Android 13+ 알림 권한, Android 14+ Foreground Service 타입 및 `FOREGROUND_SERVICE_SPECIAL_USE` 선언을 확인합니다.
- `Notification.VISIBILITY_PUBLIC`과 `setPublicVersion()`이 적용되더라도 **삼성 One UI가 전체 커스텀 레이아웃을 그대로 보여준다는 보장은 없습니다**.
- **알림 채널 ID를 매번 바꾸지 않습니다.** 변경이 꼭 필요할 때만 마이그레이션 목적·중요도·사용자 설정 영향까지 확인합니다. 이미 만든 채널의 중요도는 앱에서 일방적으로 올릴 수 없습니다.
- 알림이 보이지 않을 때에는 앱의 **알림 진단**에서 (1) 운동 진행 중인지, (2) OS에 실제 게시됐는지, (3) 카드 알림 오류 기록, (4) 채널 상태를 확인합니다.
- **카드 디자인과 잠금화면 표시 성공 여부는 각각 별개의 테스트 항목**입니다.

### C. 빌드는 성공하는데 실기기에서 계속 실패

- `assembleDebug` / `assembleRelease`의 성공은 **컴파일 결과일 뿐 앱 실행 보증이 아닙니다**.
- `.github/workflows/android-smoke.yml`에서 **연속 실행 3회 → 운동 시작 → Foreground Service 실행 → 알림 존재 → 운동 중 재실행**을 통과해야 합니다.
- 로그에 `FATAL EXCEPTION`, `AndroidRuntime`, `BadForegroundServiceNotificationException`, `RemoteServiceException`, `InflateException`이 없는지 검사합니다.
- 에뮬레이터의 알림 권한 팝업 등이 자동 UI 클릭을 막을 수 있으므로 테스트 스크립트에서 권한·UI 상호작용을 제어하고, **자동화 도구 오류와 앱 실제 크래시를 분리**합니다.
- 에뮬레이터 스크린샷과 `dumpsys notification`은 **알림 게시/화면 렌더링의 근거**이며, 삼성 갤럭시의 잠금화면 동작까지 입증하지는 못합니다.
- 앱이 실행되지 않으면 AndroidRuntime 스택트레이스, `CrashReporter` 기록을 먼저 확보합니다. **추측으로 채널 ID 변경·앱 삭제·반복 배포하지 않습니다**.

### D. APK 설치 실패 / 매번 재설치해야 함

- 구 버전의 임시 디버그 서명과 정식 고정 서명 APK는 **서명 불일치로 덮어쓰기가 불가능**했습니다.
- 이후 배포는 항상 동일한 **고정 서명 키의 `release` APK**만 사용합니다. CI의 `debug` APK는 테스트 전용입니다.
- `applicationId = com.move60.workout` 고정, **`versionCode` 증가**, release signingConfig 확인.
- 서명 키 자체, keystore, 암호, GitHub PAT를 코드·README·이슈·로그·공개 저장소에 올리지 않습니다.
- 사용 중인 운동 기록/설정 보호가 우선입니다. **삭제/데이터 초기화 전에는 사용자 확인을 받습니다**.

### E. GitHub 빌드 및 업데이트 배포의 문제

- 소스는 **비공개** `yebyn98/MOVE60-Android`; 공개 APK 배포는 **공개** `yebyn98/MOVE60-Updates`.
- GitHub Actions에서 동일한 서명 키를 쓰도록 **Repository Secrets** `MOVE60_SIGNING_BUNDLE_BASE64`을 사용합니다. ZIP 자체나 잘못된 Base64 값을 Secret에 넣으면 복원 실패합니다.
- 공개 저장소 갱신용 `MOVE60_UPDATES_PAT`를 `MOVE60-Android`의 **Repository Secrets**에 보관합니다. 토큰은 `MOVE60-Updates` 저장소에만 최소 쓰기 권한 부여.
- 공개 파일: `MOVE60-latest.apk`, `latest.json`. 매니페스트의 `versionCode`, `versionName`, `apkUrl`, `sha256` 확인.
- SHA-256은 실제 게시된 APK와 일치해야 하며, 사용자 단말의 설치 승인 절차는 유지됩니다.
- 구버전 빌드가 신버전 APK를 덮어쓰지 않도록 `build-apk.yml`의 동시 실행/구 커밋 배포 차단 규칙을 확인합니다.
- **현재 주의:** 빌드/배포 워크플로와 에뮬레이터 테스트 워크플로는 독립 실행됩니다. 따라서 **빌드 성공만으로 배포를 안전하다고 판단하지 말고 런타임 테스트 성공까지 반드시 확인**해야 합니다. 자동 배포를 실사용에 확대하기 전에는 런타임 테스트 통과를 배포의 기술적 필수 조건으로 연결하는 것이 좋습니다.

### PC에서 워치 APK 설치

1. PC와 워치를 동일한 Wi-Fi에 연결한다.
2. 워치 설정 → 워치 정보 → 소프트웨어 정보 → 소프트웨어 버전을 5번 눌러 개발자 옵션을 활성화한다. 메뉴명은 One UI 버전에 따라 다를 수 있다.
3. 개발자 옵션에서 ADB 디버깅 및 무선 디버깅을 켠다.
4. 무선 디버깅 → 새 기기 페어링에 나온 주소로 `adb pair` 실행 후 페어링 코드를 입력한다.
5. 무선 디버깅 기본 화면에 표시된 연결 주소로 `adb connect` 실행. 페어링 포트와 연결 포트를 구분한다.
6. 다운로드한 APK가 있는 폴더에서 아래 명령을 실행한다. IP/포트는 실제 워치 값으로 바꾼다.

```bash
adb pair WATCH_IP:PAIRING_PORT
adb connect WATCH_IP:CONNECTION_PORT
adb -s WATCH_IP:CONNECTION_PORT install -r MOVE60-Watch4-latest.apk
adb -s WATCH_IP:CONNECTION_PORT shell am start -n com.move60.workout/com.move60.watch.WatchActivity
```

- 설치 성공 후 워치 앱 목록의 **MOVE60 Watch**를 열고 센서 권한을 허용한다.
- 서명 충돌 등 설치 실패 시 오류 문구를 확보한다. 기존 앱 삭제/데이터 초기화를 기본 해결책으로 사용하지 않는다.
- 참고: https://developer.android.com/training/wearables/get-started/debug-wifi

## 9. v23.0 심박수 위치 및 워치 지속 측정

- v22.0 하단 고정 컨트롤 유지. 휴대폰 타이머 남은 시간 오른쪽에 심박수 박스를 배치하고 '지금 할 운동' 내부 심박수 문구를 제거한다.
- 유효한 센서 측정값이 없거나 마지막 측정이 10초를 넘으면 '연결대기'로 표시한다. 워치는 마지막 실제 측정 경과 초도 표시한다.
- 기존 단기 MeasureClient를 SensorManager.TYPE_HEART_RATE + health 포그라운드 서비스로 교체한다. 센서 이벤트마다 워치 값을 갱신하고 실제 측정 시각과 함께 휴대폰으로 전달한다. 임의 숫자를 생성하거나 마지막 값의 시각만 갱신하지 않는다.
- WatchActivity.onPause에서는 측정을 중단하지 않는다. 운동 중 워치 화면에는 FLAG_KEEP_SCREEN_ON을 적용하며, 화면을 수동으로 꺼도 서비스는 유지된다.
- 센서/BODY_SENSORS 권한이 필요하다. API 33 이상에서는 화면 밖 측정을 위해 앱 권한 → 센서 → '항상 허용' 설정을 안내한다. 워치 앱의 권한 설정 링크로 재진입할 수 있다.
- 알림의 '측정 중지'로 서비스를 종료할 수 있다. 운동이 진행 중이지 않고 워치 화면도 벗어나 있으면 90초 뒤 종료한다. 단일 측정 세션은 최대 3시간으로 제한해 방치 시 배터리 소모를 줄인다.
- 화면 꺼짐 중 센서 전달 유지를 위해 측정 중에만 PARTIAL_WAKE_LOCK을 보유하고 서비스 종료 시 해제한다.
- 휴대폰 일시정지/종료 시 워치에도 정지 상태를 즉시 게시한다.
- 실제 센서 표본 간격은 워치 하드웨어/착용 상태/OS에 따른다. 초당 BPM 변화나 삼성 헬스와 수치 일치를 보장하지 않는다.
- 실기기 확인: 양쪽 v23 설치 → 워치 센서 권한 → 휴대폰 운동 시작 → 2분 이상 BPM/측정 경과 확인 → 워치 화면 수동 끄기/앱 나가기 후 휴대폰 수신 유지 → 재진입 상태/화면 유지 → 일시정지 및 측정 중지 시 센서·wake lock 해제 확인.
- 센서 없는 에뮬레이터 컴파일·휴대폰 UI 테스트는 실제 워치 심박 측정/화면 밖 수신 성공의 증거가 아니다.

## 10. v24.0 워치 운동 화면 유지·현재 단계·원형 화면 잘림 수정

- '계속 밝게 켜기' 대신 OngoingActivity + AmbientLifecycleObserver를 사용한다. 운동 중(일시정지 포함) 진행 알림과 시계 화면 복귀 아이콘을 제공하고, 저전력 상태에는 검은 배경 위 현재 단계·남은 대략적인 분·시각을 표시한다.
- 저전력 화면에는 갱신되지 않는 초 단위 타이머나 심박수 숫자를 표시하지 않는다. 손목을 들어 활성 상태로 돌아오면 실제 남은 시간과 최신 심박수를 다시 표시한다.
- 화면 유지용 WorkoutDisplayService는 센서 권한과 독립적이다. 실제 보안 PIN 잠금을 우회하지 않는다. Always On Display가 꺼진 경우 화면 자체는 꺼질 수 있고, OS/One UI 버전에 따라 복귀 동작이 다르므로 워치4 실기기 확인이 필요하다.
- 원형 화면에 내접하는 안전 영역 안에 '1/4 준비운동 → 2/4 유산소 → 3/4 근력운동 → 4/4 마무리 스트레칭', 상세 구간, 남은 시간, 심박수, 시작/일시정지·다음 단계를 배치한다.
- 다음 버튼은 마지막 단계에서 '운동 완료'로 표시한다. 두 버튼은 각각 높이 44dp로 구성한다. 큰 글꼴/작은 화면에서는 본문 스크롤로 접근 가능하게 한다.
- 단계 제목을 길게 누르면 센서 권한 설정과 심박수 측정 중지 메뉴가 열린다.
- 폰→워치 전송에 단계 번호·단계 이름·상세 구간·일시정지 남은 시간·운동 완료 여부를 추가한다. 초 단위 남은 시간은 고정 마감 시각을 기준으로 계산해 동기화마다 다시 늘어나지 않게 한다.
- 양쪽 v24 업데이트 후 워치 앱을 한 번 열어 운동 화면을 연결한다. 알림 허용이 필요하다.
- 릴리스 게이트는 Wear OS API 34 작은 원형 에뮬레이터에서 396×396 / 330dpi(약 192dp) 기준 네 단계·두 버튼 안전 영역·저전력/복귀 레이아웃·고정 마감 시각·진행 알림 복귀를 검사한 뒤 기존 휴대폰 검사를 수행한다.
- 자동 저전력 진입/시계 화면 복귀 차단 및 실제 센서 수신은 삼성 워치4에서 별도 확인한다. 에뮬레이터의 저전력 레이아웃 테스트는 콜백에 따른 UI 전환을 검증하며 실제 손목 제스처를 입증하지 않는다.


## 11. v25.0 운동 화면·세트 기록·일별 칼로리

- 하단 고정 컨트롤에 오늘의 누적 운동 칼로리 추정치를 실시간 표시한다. 일시정지 시간은 제외하며 서비스 체크포인트 중복 집계를 막고 한국 시간 자정 기준으로 분리한다.
- 스텝밀 선택일은 보통/좋음 15분, 피곤 10분으로 제한한다. 나머지 유산소 시간은 실내 사이클로 배정하며 총 60분을 유지한다. 원본 데이터는 보존하고 런타임 구성에 사용자 요청 예외를 적용한다.
- 운동 달력은 실제 운동 시간이 기록된 날에 연두색 점을 표시한다.
- 알림 진단·업데이트·시간 배분·체중·알림음·컨디션·오류 기록은 앱 설정 버튼으로 여는 내부 SettingsActivity로 이동한다.
- 마지막 단계는 활성화된 운동 종료 버튼을 표시한다.
- 첫 화면의 각 근력 세트에서 중량(맨몸 0kg), 횟수, RPE를 입력하고 첨부 HTML과 같은 연두색 기본 체크박스로 완료를 표시한다. 자동 저장하고 타이머 갱신 시 입력 필드를 재생성하지 않는다. 날짜/요일/운동 세션/종목/세트별로 기록한다.
- 칼로리는 실제 시간·체중·MET 기반 총 에너지 추정치다. 근력 기본값 3.5 MET, 완료 세트가 있으면 반복 1회 3초 가정, RPE 7 이상 6 MET/미만 3.5 MET, 나머지 휴식 1.5 MET를 적용한다. 반복 시간은 실제 근력 시간 이하로 제한한다. 개인별 보정 모델이 아니며 세트 수정 시 날짜별 추정치가 재계산된다.
- 중량×횟수는 운동량(kg·회)으로 기록한다. 중량을 열량으로 직접 환산하지 않으며 개인 보정이 없는 심박수도 열량에 합산하지 않는다. 심박수 실시간 표시는 유지한다. 이전 버전의 시간 기록은 구간 정보가 없어 4.5 MET로 추정한다.
- 근거: 2024 Adult Compendium 저항 운동 MET 범주 https://pacompendium.com/conditioning-exercise/ . 실제 에너지 소비 측정값으로 해석하지 않는다.
- 휴대폰 계측 테스트 7개(설정 이동, 마지막 종료, 입력 유지/재실행, 달력 점, 시간 배분별 스텝밀 제한, 열량 중복 방지/재계산, 세션 기록 분리)를 추가하고 기존 Wear 4개 및 휴대폰 스크롤/고정 컨트롤 검사를 유지한다.


## 12. v26.0 현재 운동 중심 화면·자동 휴식·양방향 세트 연동

- 첫 화면의 소개/중복 요약을 줄이고 현재 단계를 먼저 배치한다. 하단 이전/시작·일시정지/다음은 한 줄의 52dp 터치 영역으로 구성하며 심박 박스와 일 누적 kcal는 유지한다. 현재 종목·세트와 입력 위치 바로가기를 제공한다.
- 근력 세트를 완료하면 종목의 휴식 시간(없으면 60초)이 시작된다. +15초/건너뛰기, 일시정지·재개, 프로세스 재실행 복원, 단계 이동·종료 시 취소를 지원한다. 휴식은 전체 실제 운동 시간에 포함된다. 자동으로 운동 단계나 세트를 넘기지 않는다.
- 종목별 지난 완료 기록의 중량/횟수/RPE를 보여주고 불러온다. 미래 날짜, 미완료 초안, 현재 세션을 제외한다. 불러오기만으로 완료 처리하거나 이미 완료한 세트를 덮어쓰지 않는다.
- 휴대폰이 기준 상태를 소유한다. 워치는 현재 종목/세트를 받고, 입력된 유효한 값이 있을 때 현재 세트를 완료할 수 있다. 휴식 중 다음 버튼은 건너뛰기이며 길게 누르면 +15초/다음 단계 메뉴가 열린다.
- 양쪽 v26 설치 필요. 워치 명령에는 요청 ID, 생성 시각, 요일, 세션 ID, 조작 버전, 단계, 종목/세트를 포함한다. 15초를 넘긴 요청, 다른 요일/세션/버전, 중복 요청은 반영하지 않고 최신 상태를 반환한다. 기존 v25의 단순 문자열 조작 명령은 받지 않는다(심박수 메시지는 호환 유지).
- 워치는 연결 확인 및 재연결 시 상태를 요청하고 ACK를 기다린다. 응답 전 중복 조작을 막으며 8초 후 응답이 없으면 상태를 다시 요청한다. 오프라인 조작은 저장·재전송하지 않는다. 조작 결과를 미리 적용하지 않고 휴대폰의 결과를 표시한다.
- 게시 순번을 영속화하고 워치 UI/진행 서비스에서 역순 스냅샷을 거부한다. 휴대폰 화면도 외부 조작 내용을 다시 읽는다. 이전 서비스 콜백이 최신 단계/세션을 덮어쓰지 않도록 최신 상태로 보정한다. 심박수도 측정 시각이 역행하는 메시지는 거부한다.
- 휴식 종료는 폰 알림/워치 진동을 한 번씩 전달한다. 늦은 복구로 10초 이상 지난 알림은 생략한다. 실제 알림·진동 시각은 OS 절전/권한/연결 상태에 영향을 받으므로 실기기에서 확인한다.
- 워치 타일은 현재 단계/종목 요약을 표시하고 탭하면 운동 화면을 연다. 초 단위 숫자는 표시하지 않는다.
- 검증: 기존 폰 7개 + 신규 5개 = 12개, 기존 Wear 4개 + 신규 3개 = 7개. 중복/오래된 명령 차단, 세트 완료→휴식→다음 세트 패킷, 휴식 중지/재개/취소, 과거 기록 선택, 원형 화면, 역순 수신 및 알림 중복을 검사한다.
- 두 에뮬레이터의 독립 계측 검사는 실제 Bluetooth/Google Play Services 페어링 성공을 입증하지 않는다. Watch4 실기기: 양쪽 v26 → 휴대폰 근력 단계 및 세트 값 입력 → 워치 세트 완료 → 양쪽 휴식 확인 → 폰/워치 일시정지·재개 → 연결 끊김 중 조작 차단 → 재연결 상태 복구 → 마지막 종료와 심박 측정시각 확인 순서로 점검한다.

## 13. v27.0 날짜별 진행 복원·첫 화면·설정 가독성

- 진행 상태를 실제 한국 날짜 + 선택 루틴으로 분리한다. 지난 날짜의 완료 상태와 요일 선택을 오늘로 복원하지 않는다. 같은 날짜의 진행/완료는 유지하며, 자정을 넘겨 진행 중인 운동은 종료 전까지 이어간다.
- 이전 주차 키는 삭제하지 않는다. 실제 시작 시각이 오늘인 기록만 새 키로 옮긴다. 시작한 적 없는 미리보기 완료와 지난 날짜 완료를 오늘로 가져오지 않는다. 활동 시간 0초로 종료한 경우 첫 화면에 '운동 종료 · 기록 없음'으로 표시한다.
- 첫 화면은 작은 현재 운동 카드 → 현재 단계 세트 입력 → 다른 단계 접기 → 요약 순서다. 큰 중복 타이머 대신 고정 하단에서 시간·심박·칼로리를 확인한다. 현재 운동 카드를 길게 누르면 단계/오늘 진행 초기화를 선택할 수 있다.
- 설정은 알림·업데이트 / 운동 설정 / 앱 정보·도움말 카드로 나눈다. 제목 18sp, 조작 16sp, 설명 14sp, 카드 간 24dp, 조작 영역 최소 56dp와 문단 간격을 적용한다.
- 날짜 회귀 검사 5개를 추가해 폰 계측 테스트 총 17개, 기존 Wear 7개와 고정 컨트롤·알림·재실행 검사를 릴리스 게이트로 실행한다. 새 스크린샷 phone-v27-home.png, phone-settings.png, phone-inline-sets.png로 배치를 확인한다.
- 실기기 잔여 확인: 업데이트 전 기록 보존, 갤럭시 큰 글꼴/키보드에서 세트 입력, Watch4 실제 심박 수신·Bluetooth 재연결·세트 양방향 조작, AOD/화면 꺼짐 후 복귀, 타일 최신 상태, 장시간 배터리 소모. 에뮬레이터 결과로 이를 완료 처리하지 않는다.


## 14. v28.0 상체·하체 선택 및 근력 전용 상세

- 첫 화면 요일 아래 상체 운동 / 하체 운동 선택을 추가한다. 실제 날짜 + 선택 루틴별로 저장하며, 다음 날짜에는 새로 선택할 수 있다. 선택하지 않은 상태는 기존 요일 기본 루틴을 유지해 이전 기록과 진행 상태를 보존한다.
- 선택하면 근력 4종목이 자동 구성된다. 상체는 가슴·등·어깨·팔, 하체는 허벅지·둔근·햄스트링·종아리/단측 운동 풀을 사용한다. 대체 운동도 선택한 부위의 풀로 제한한다. 기존 유산소/스텝밀 제한과 총 60분은 유지한다.
- 운동 시작 후에는 일시정지 중에도 부위를 바꾸지 않는다. 종료 후 선택하면 새 준비 상태로 전환하며 과거 세트/달력/칼로리 기록은 삭제하지 않는다. 선택은 조작 버전을 갱신하고 워치에 최신 종목과 상체/하체 단계 이름을 전송한다.
- 상세 버튼 및 운동명 상세 진입은 근력운동에만 제공한다. 준비/유산소/마무리에는 상세 진입을 제거한다.
